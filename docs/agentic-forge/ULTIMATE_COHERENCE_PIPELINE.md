# Ultimate Coherence / Non-Destructive Expansion Pipeline

## 1. The central idea

The system can grow continuously, but growth is not authority.

An external reference is observed from outside the canonical project. Once ingested, it becomes an **internal reference object** for analysis. It does not become an internal authority.

This gives two simultaneous viewpoints:

- **external provenance:** where the information came from and what its original context was;
- **internal perspective:** how that information relates to the canonical project state.

The boundary is explicit:

`External Reference ightarrow Internal Object 
eq Internal Authority`

The system therefore can absorb references without surrendering its own invariants.

## 3. Self-expansion without self-destruction

"Self-expanding" means that the system can discover additional **work, references, capabilities, dependencies and refinement opportunities** from its current frontier.

It does **not** mean:

- arbitrary self-modification;
- permission escalation;
- deleting old state;
- replacing the canonical reference without verification;
- enabling Internet access;
- executing every discovered upstream;
- treating generated suggestions as facts.

Expansion is bounded by policy, resources, verification and human approval for protected transitions.

## 4. Coherence closure

A candidate is not accepted because it looks useful.

It must close the relevant dependency set:

```
candidate
 + provenance
 + policy
 + dependencies
 + temporal consistency
 + resource feasibility
 + verification
 + security
 = coherence closure
```

If closure fails, the candidate remains a candidate or enters quarantine.

## 5. Non-destructive refinement

A new reference may reveal that an existing implementation can be improved.

The system creates:

```
CURRENT STATE
     │
     ├── TimeWarp branch A: existing state
     └── TimeWarp branch B: proposed refinement
                    │
                 verify
                    │
              compare/close
                    │
          explicit promotion
```

The old accepted checkpoint remains archived.

Therefore refinement is **additive before it is substitutive**.

## 6. Reference duality

The unusual but useful property is that an external reference has two identities at once:

```
SOURCE IDENTITY
    ↓
external provenance
    ↓
internal reference object
    ↓
internal projections
    ├── semantic
    ├── temporal
    ├── causal
    ├── structural
    ├── resource
    ├── security
    └── coherence
```

Its origin remains external while its representation becomes internal.

This avoids the false choice between "ignore external knowledge" and "let external knowledge control the system."

## 7. Recursive frontier

The project maintains a frontier:

- unresolved dependencies;
- missing capabilities;
- unverified hypotheses;
- useful external references;
- coherence conflicts;
- possible optimizations;
- incomplete verification.

Each frontier item is either completed, rejected, quarantined, deferred, or recursively decomposed.

No arbitrary number of children is required.

`Can this item be completed in one iteration?`

- yes → leaf iteration;
- no → causal decomposition;
- repeat until every leaf is independently verifiable.

## 9. Ultimate invariant

The core rule is:

> **The system may enlarge its representation of reality without silently enlarging its authority over reality.**

More references can be added.

More capabilities can be discovered.

More branches can be tested.

More context can be reconstructed.

But an accepted internal invariant changes only through an explicit, provenance-preserving, verifiable and reversible transition.

## 10. Current security posture

The pipeline remains compatible with the existing deny-by-default model:

- network: denied;
- external MCP: denied;
- OAuth: denied;
- self-escalation: denied;
- external code: reference-only until reviewed;
- protected writes: human approval;
- accepted history: immutable;
- rollback: non-destructive.

This makes expansion a controlled process of **representation → comparison → verification → promotion**, rather than uncontrolled self-modification.

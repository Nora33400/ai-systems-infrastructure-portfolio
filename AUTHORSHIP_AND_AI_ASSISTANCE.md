# Authorship and AI Assistance

The portfolio author directed the problem definitions, system constraints, architecture choices, acceptance criteria, evidence selection, and release boundaries represented here.

AI coding assistants and local/hosted language models were used extensively for implementation drafts, documentation, test generation, refactoring suggestions, and debugging support. AI-generated volume is not treated as evidence of engineering quality. Claims are based on inspectable source, executed tests, measured artifacts, and explicitly stated limitations.

The author’s demonstrated role is to frame problems, constrain tool behavior, compare implementations with requirements, run and interpret tests, preserve negative results, correct defects, and decide what evidence is strong enough to publish. Examples in this copy include rejecting generated runtime bulk, repairing a TimeWarp indentation defect, preserving a FractalOS mesh defect as an expected failure, and retaining Opti’s redaction-related hash discrepancy as historical negative evidence.

Limitations remain: not every copied historical line has independent authorship verification, benchmarks are mostly project-designed, and the repository does not establish independent scientific novelty or production-scale cluster operation. File-level reuse therefore requires the provenance review described in [LICENSE](LICENSE) and [SELECTION_AND_PROVENANCE.md](SELECTION_AND_PROVENANCE.md).
